# Idea Brief: Canopy - The Flight Deck for Agentic Coding

## Problem Statement

Traditional source code editors (vim, emacs, VSCode) are designed for line-by-line code editing, but the rise of agentic coding has fundamentally shifted how developers work. Today's developers spend their time defining requirements, designing architecture, and orchestrating AI agents—not writing code character by character. Current editors force developers to work at the wrong level of abstraction, showing files and syntax when they need to see systems and relationships.

## Target Users

**Primary users:** All programmers embracing agentic coding, regardless of experience level.

**Pain points:**
- Navigating codebases at the file/line level when their actual work happens at the component/system level
- Context-switching between architectural thinking and low-level code navigation
- No unified view of what components exist, what they do, and how they connect
- Existing tools bolt AI features onto legacy editors rather than rethinking the paradigm

## Proposed Solution

**Canopy** is an open-source, AI-native TUI that presents codebases as C4-style architectural views (systems → containers → components) instead of files and folders. Human-language summaries of responsibilities, dependencies, and relationships are front-and-center. Code becomes the deepest layer, accessed only when needed.

The AI generates everything first; developers edit or augment as needed, with clear provenance tracking. Point Canopy at any repository—zero configuration required—and immediately see the architectural shape of the codebase.

## Key Features

- **C4-style hierarchical view** — Navigate systems, containers, and components, not directories and files
- **AI-generated semantic layer** — Responsibilities, dependencies, test coverage, and recent changes in plain language
- **Natural language interaction** — Ask questions about the codebase via text box with `@component` mentions
- **Vim-style navigation** — Familiar keyboard-driven interface with search/filter
- **JSONL edit log** — Every structural edit captures what, why, and timestamp for future agent-driven refactoring
- **Language-agnostic** — Leverages LLM code understanding; supports whatever the backing models support

## Success Criteria

- Developers spend the majority of their development time in Canopy
- Measurable productivity gains when using agents due to working at the right abstraction level
- Successful dogfooding: Canopy is built and navigated using Canopy itself
- Community adoption as an open-source project

## Open Questions

- **Optimal navigation UX** — Tree view may not fit graph-like codebase relationships; requires experimentation
- **C4 inference accuracy** — How reliably can LLMs infer architectural structure from code organization?
- **Confirmation UX** — Finding the right balance for AI inference confirmation without breaking developer flow
- **"Calm flight deck" aesthetic** — Achieving the desired emotional experience in a TUI is uncharted territory
